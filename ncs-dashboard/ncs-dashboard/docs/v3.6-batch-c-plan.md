## 第 1 章 · 范围边界

原则一句话：

> **Batch C 可以改变「显示多少标签、占多少空间」，不能改变「数据是什么」。**

| 做 | 不做 |
|---|---|
| Top10 展示结构与滚动 | 不改排序 / DTO / 契约 |
| 右栏四 Panel 高度机制 | 不改三模式判定（`detectMode`） |
| Label 去重 + 异常字号收敛 | 不删任何 series 数据点 |
| Tooltip 必要时微调 | 不改字段语义 |
| — | 图表配色 / Heatmap 全蓝 / Donut 居中 → Batch D |
| — | API / Adapter / Mock / `interpolation.js` / `useEChart.js` → 零改动 |

**硬性禁令**（写在每个改动点旁）：
- `LoadForecastChart` 的 PCHIP、置信区间重构、cutoff 语义**一行不改**（Batch A 已封存）。
- 抽稀只作用于 `axisLabel`，**绝不能落到 `series.data`**。
- 最后一项数字列仍叫 **「充电费用」**，不得写成 revenue / 营收 / 收入。

## 第 2 章 · C1：Top10 改造成「固定窗口 + 内部滚动」

### 2.1 实测确认的两个真 bug

`dashboard.css` 现为 `.ranking-list { height:100%; grid-template-rows: repeat(10, minmax(0,1fr)); }`

| bug | 实测证据 |
|---|---|
| **10 轨道空洞** | 运行时隐藏第 10 行 → 容器 244.4px，9 行 + 8 gap 仅占 216.3px，**底部空洞 28.1px** |
| **行高随容器漂移** | 行高 14.8px（1280×800 变换后）～35px（390×844），**摆动 2.4 倍** |

契约核实（决定边界）：`adaptStationRanking` 强制 `rank` 从 1 连续、`items.length ≤ 10`（超过抛 `ApiProtocolError`），`meta.empty` 时 `status='empty'` 走 `PanelState` 不渲染列表。
⇒ **`items.length ∈ [1,10]`，必须同时正确支持 1 行与 10 行。**

### 2.2 结构：flex 列表（不用 grid）

Top10 本质是列表，flex 对「max-height + 滚动」的表达最直接：

```css
.ranking-list {
  --rank-row-h: 26px;
  display: flex;
  flex-direction: column;
  gap: 3px;
  min-height: 0;
  overscroll-behavior: contain;
  padding: 0 5px 4px;
  /* 删除 grid-template-rows: repeat(10, ...) 与 height:100% */
}
.ranking-row {
  flex: 0 0 var(--rank-row-h);
  /* 内层 grid 由 minmax(17px,1fr) 2px 改为 minmax(0,1fr) 2px，
     否则固定行高下 17px 最小值会把轨道顶出盒子 */
  grid-template-rows: minmax(0, 1fr) 2px;
}
```

三点必须一起改：删 `repeat(10,…)`（修空洞）、删 `height:100%`（否则容器仍是父高）、父行 `fr → auto`（否则外框仍被撑开）。

### 2.3 模式差异（关键）

| 模式 / tier | `--rank-row-h` | `max-height` | 内部滚动 | 可见行数 | 面板高度由谁决定 |
|---|---|---|---|---|---|
| scale | 26px | 158px | ✅ `auto` | 5 行满 + 第 6 行露头 | 列表 `max-height` 封顶 → **204px** |
| compact / columns | 28px | 197px | ✅ `auto` | 6 行满 + 第 7 行露头 | 列表 `max-height` 封顶 → **243px** |
| compact / stack | 30px | **none** | ❌ `visible` | 10 行自然展开 | 内容驱动 + `min-height:380px` → **380px** |
| reflow | 36px（两行版） | **none** | ❌ `visible` | 10 行自然展开 | 内容驱动 + `min-height:460px` → **≥460px** |

**为什么 stack / reflow 取消内部滚动**：手机/窄屏整个页面本就在纵向滚动，再套一层内部滚动会出现「页面滚动 + 列表滚动」双重滚动，操作别扭。这一条前稿已识别，此处固化为冻结项。

### 2.3.1 ★ 面板高度预算（**前稿遗漏 stack，此处补齐**）

面板 chrome 已**实测**（不是推算）：

```text
header        40px   ← .dashboard-column--right .panel-header--compact
body padding  1 + 5 = 6px
list padding-bottom 4px
⇒ chrome = 46px
面板高度 = 行数 × rowH + (行数−1) × gap + 4 + 46
```

10 行时的需求 vs 现状（**现状全部来自实测探针**）：

| 模式 / tier | rowH | 10 行列表 | **面板需求** | 现状 | 差额 |
|---|---|---|---|---|---|
| scale | 26 | 287 | **337** | 292 | → `max-height:158` → 204 ✅ 释放 88px |
| columns 1715×1401 | 28 | 307 | **357** | 396 | → 243 ✅ **释放 153px** |
| columns 1600×1200 | 28 | 307 | **357** | 322 | → 243 ✅ 释放 79px |
| columns 1280×1024 | 28 | 307 | **357** | 258 | → 243 ⚠️ 该档本就最挤，见 R3 |
| **compact / stack** | 30 | 327 | **377** | **300** | ⚠️ **裁 77px ← 前稿遗漏项** |
| **reflow** | 36（两行） | 387 | **437** | **420** | ⚠️ **裁 17px** |

> 前稿只给了 reflow 的 `420 → 460`，漏了 stack。且前稿按「header 48 + padding 10 = 58」估算 chrome，
> 实测是 **46px**，故 stack 的实际缺口（77px）比按前稿口径估的（40~50px）更大。

**结论：scale / columns 靠 `max-height` 封顶反而**释放**高度；stack / reflow 因为不设 `max-height`，
必须由内容驱动，绝不能再压回 `max-height`，也不能沿用旧的固定高度。**

#### 为什么 stack / reflow 仍给一个显式 `min-height`

理论上「父行 `auto` + 列表 `height:auto`」就是纯内容驱动，不需要 min-height。
但 `.dashboard-panel` 是 `flex-direction:column`，其 `body` 是 `flex:1`（等价 `flex-basis:0%`）；
**列向 flex 容器在 `auto` 高度下的 intrinsic sizing 各引擎实现有差异** —— Batch B 的 R2
（`height:100%` 在无高度约束的 flex 列中塌缩为 0）就属这一类。

因此给 `min-height` 作为**确定性下界**：

```text
stack  ：min-height: 380px   （需求 377 + 3 余量）
reflow ：min-height: 460px   （需求 437 + 23 余量）
```

`min-height` 而非 `height` ⇒ 内容再多也不会被裁；若引擎的 intrinsic 算少了，由下界兜住。

#### 连带影响

stack 档右列最小高：`300+200+160+140 + 3×10 = 830px` → `380+200+160+140 + 30 = 910px`（**+80px**）。
compact **允许纵向滚动**，页面长 80px 无副作用；已于 1024×768 / 900×600 两档确认无横向溢出。

### 2.4 Reflow 两行版（390px 不硬撑单行）

单行 `1 站名 334单 2098kWh ¥328` 在 390px 下装不下，改为两行：

```text
[1] 科学大道充电站
    334单 · 2098.4kWh · ¥328.60
```

实现（显式 grid 定位，数据字段一个不少）：

```css
[data-layout='reflow'] .ranking-row {
  grid-template-columns: 22px 62px 84px minmax(0, 1fr);
  grid-template-rows: auto auto 2px;
}
[data-layout='reflow'] .ranking-index   { grid-row: 1 / 3; grid-column: 1; }
[data-layout='reflow'] .ranking-station { grid-row: 1; grid-column: 2 / -1; }
[data-layout='reflow'] .ranking-orders  { grid-row: 2; grid-column: 2; }
[data-layout='reflow'] .ranking-energy  { grid-row: 2; grid-column: 3; }
[data-layout='reflow'] .ranking-fee     { grid-row: 2; grid-column: 4; }
[data-layout='reflow'] .ranking-track   { grid-row: 3; grid-column: 2 / -1; }
```

**连带改动（易漏）**：reflow 下 StationRanking 的面板是硬编码 `height: 420px`。
两行版 10 行需 `10×36 + 9×3 + 4 = 387px`，加 chrome 46 = **433px > 420px**，会被 `overflow:hidden` 静默裁掉 13px。
⇒ **改为 `height: auto` + `min-height: 460px`**。

用 `min-height` 而非继续猜一个固定 `height` 的理由：
- 需求 433px 与旧值 420px 只差 13px，**留在同一量级 ⇒ 字体 / border / `box-sizing` / 滚动条任何一项都足以吃掉这点余量**；
- reflow 页面本就是长页面，多给 20~30px 的纵向成本近似为零，但换来「永不裁切」；
- 若做成死 `height`，将来行数或字号一改就会重新出现静默裁切，而这类缺陷**截图/断言都不易发现**（Batch B.1 的 250px 纵向溢出就是这么漏过去的）。

`min-height` 让下界可信、上界由内容决定，把「猜一个够大的数」换成「保证不小于需求」。

>

> 取值 **1100**，并必须同步：

> - 复验 `1024×1366` 等「窄而高」的视口 —— 阈值上调会把它们从 columns 推到 stack，需确认是改善而非劣化；

#### R14（滚动条位移）实测结论：**暂不加 `scrollbar-gutter`**

```
1920×1080 / 1715×1401 / 1280×1024
  3 行（无滚动条） vs 10 行（有滚动条）
  → 列表 gutter 0px，数字列位移 0px
```

⚠️ **但该结论有一个必须说明的前提**：headless Chromium 使用 **overlay 滚动条**，即使加 `--disable-features=OverlayScrollbar` 也测不到经典滚动条占位（`offsetWidth − clientWidth` 恒为 0），元素截图里也确实看不到滚动条。因此**该测量只能证明「overlay 下无位移」，不能证明真实桌面 Edge 下无位移**。

若真实 Edge 渲染的是经典 8px 滚动条（`::-webkit-scrollbar { width: 8px }` 已设），则当 `items.length` 在「≤5 行（不滚）」与「>5 行（滚）」之间切换时，数字列会横向位移 8px。合同允许 `items.length ∈ [1,10]`，所以这种切换在理论上是可能的。

→ **按「有位移才加」的口径，本批不加**（无复现证据）；但把它登记为残余项：若在真实浏览器里看到数字列在刷新后跳 8px，一行 `scrollbar-gutter: stable` 即可消除。

### D2. ★★ 两次失败的修法（同一机理，勿再试）

```text
若 因子 × 假想fr尺寸 < 下界  ⇒ 退回下界（无富余的档位：完全不长）

```

在能给的档位自动成立，在给不了的档位自动不生效**。
