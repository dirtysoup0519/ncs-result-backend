## 1. 当前结论

项目当前基线是 ADS v2.5（18 个数据集）到虚拟机 MySQL、Flask 查询 API、Vue 大屏和外部模型推理的闭环。Windows 手工导入与虚拟机 Shell 自动同步共用同一套校验、导入和发布内核。

当前业务边界固定为：接收上游已经处理完成的数据，负责结果库存储、校验、发布、回滚、管理后端、大屏查询后端，以及使用外部训练好的模型执行受控推理。ODS/DWD/DWS/ADS 加工、模型训练、调参和效果评估不属于本仓库。

## 3. 当前可用链路

```text
ADS v2.1 交接包
  -> 包完整性与对账校验
  -> A0 / Wave B 显式转换
  -> MySQL rpt_* 结果表
  -> ctl_* 批次、质量与发布记录
  -> api_v1_* 只读视图
  -> Flask 查询 API
  -> Vue / ECharts 大屏
```

最新设计支持双入口：数据管理程序既可在 Windows 读取本地交接包并远程写虚拟机 MySQL，也可部署到上游虚拟机读取本地 ADS/HDFS 后就地写库；Windows Flask 始终通过虚拟机 IP 查询。Shell 通过 `.ready` 标记触发批次导入，成功后可自动触发预测。详细设计和实测状态见 `双运行位置数据接入设计.md` 与 `ADS_v2.5自动同步与模型推理设计.md`。

### 双入口幂等验收工具（已就绪，待上机）

`scripts/verify_dual_entry_idempotency.py` 覆盖原 P0-1 和 P5 的验收内容：

- 首次导入：经 CLI 入口（与 Shell 同步同款路径）发布全部数据集。
- 双入口幂等：同一批次再经管理服务入口（`AdsV23ImportService`）与 CLI 入口重复提交，数据库状态必须不变。
- 失败回滚：构造在事务插入中途失败的坏包（`stat_hour=24`），验证完整回滚、旧发布保持可读、零残留。
- 顺带验证同批次不同校验和的拒绝防护。

本地 SQLite 预演结果：18 批次 / 18 发布，重复提交与失败注入后状态零变化。上机执行（虚拟机内）：

```bash
python scripts/verify_dual_entry_idempotency.py \
  --database-url 'mysql+pymysql://root@127.0.0.1:3306/ncs_analytics'
```

不提供 `--package` 时自动合成满足跨文件对账规则的 18 数据集 v2.5 样例包；也可用 `--package` 指向真实交接包目录。
