# 数据库简易管理窗口设计

> 状态：首版已实现并通过本地测试；本文同时保留设计依据和后续可选项
>
> 目标：以最低成本提供远程 MySQL 连接状态、日志查看和 SQL 执行能力
>
> 使用范围：学生实践、本机或受控测试环境，不作为生产数据库管理器

## 1. 方案结论

该 UI 已按 Flask 单页工具实现，没有建立独立 Vue/React 项目。当前部署已冻结为“虚拟机 MySQL、Windows 外部访问”，因此 Windows 窗口不负责数据库进程启停。

页面只保留三个功能：

1. 查看虚拟机 MySQL 的地址和连接状态。
2. 输入并执行一条 SQL，显示结果或影响行数。
3. 查看本工具产生的数据库操作日志。

不实现用户、角色、审批、监控图表、Schema 设计器、备份中心等功能。这样既满足实践演示，也不会让管理窗口本身超过结果库后端的工作量。

## 2. 一个必须明确的限制

SQLite 是嵌入式数据库，没有可启动或停止的服务。虚拟机内的 MySQL 也不能由 Windows 的本地服务命令管理。

MySQL 的启动、停止和重启必须登录虚拟机后执行。Windows 数据库窗口仅用 `SELECT 1` 探测连接，不调用 `sc.exe`，也不通过任意远程命令控制虚拟机。

因此当前固定隐藏启停按钮，状态接口返回 `startStopSupported=false`。SQLite 仍用于本地自动化测试，不代表答辩部署拓扑。

页面使用 Flask 模板、原生 CSS 和少量 JavaScript，不需要 Node.js 构建。

## 4. 页面行为

### 4.1 数据库状态和启停

- 页面加载时获取数据库状态。
- 点击启动、停止或重启后，按钮进入等待状态。
- 后端执行固定的运行方式，不接收用户输入的系统命令。
- 操作完成后再次测试数据库连接，以实际连接结果作为最终状态。
- 停止和重启弹出一次简单确认。

### 4.2 SQL 输入框

- 一次只执行一条 SQL。
- `SELECT`、`SHOW`、`DESCRIBE` 返回表格。
- `INSERT`、`UPDATE`、`DELETE` 和 DDL 成功后提交事务并返回影响行数。
- 执行失败自动回滚并显示数据库错误。
- 查询结果最多显示 500 行，避免浏览器卡死。
- 输入框支持 `Ctrl+Enter` 执行。
- 页面检测到 `DROP`、`TRUNCATE` 或不带 `WHERE` 的 `DELETE` 时要求再次确认；后端仍以数据库事务结果为准。

这是直接 SQL 工具，因此只允许监听 `127.0.0.1` 或在可信局域网内临时运行。不要将该页面直接暴露到公网。

### 4.3 日志窗口

日志只记录这个管理工具执行的操作：

- SQL 执行时间、是否成功、耗时、返回/影响行数和错误摘要。
- 连接状态检查；历史启停接口保留兼容说明，但当前虚拟机部署不启用。
- 工具启动和数据库连接失败。

首版由浏览器每 2 秒拉取一次最近日志，不实现 WebSocket。后端保留最近 500 条内存日志，同时写入普通日志文件，程序重启后仍能查看历史文件。

## 6. 接口合同

### 6.1 获取状态

`GET /internal/db-console/status`

```json
{
  "code": "OK",
  "data": {
    "databaseType": "mysql",
    "runtimeMode": "docker",
    "runtimeStatus": "RUNNING",
    "connectionStatus": "CONNECTED",
    "databaseName": "ncs_result",
    "startStopSupported": true,
    "checkedAt": "2026-09-14T14:00:00+08:00"
  }
}
```

状态枚举：

- `runtimeStatus`：`RUNNING`、`STOPPED`、`STARTING`、`STOPPING`、`UNKNOWN`。
- `connectionStatus`：`CONNECTED`、`DISCONNECTED`。

### 6.2 启停数据库

`POST /internal/db-console/runtime`

请求：

```json
{
  "action": "RESTART"
}
```

`action` 只允许 `START`、`STOP`、`RESTART`。浏览器不能提交服务名、程序路径或命令参数，这些值固定在后端配置中。

响应：

```json
{
  "code": "OK",
  "data": {
    "action": "RESTART",
    "runtimeStatus": "RUNNING",
    "connectionStatus": "CONNECTED",
    "durationMs": 2180
  }
}
```

不支持启停时返回：

```json
{
  "code": "DB_RUNTIME_NOT_MANAGED",
  "message": "当前数据库由外部环境管理，不能从本工具启停"
}
```

### 6.3 执行 SQL

`POST /internal/db-console/sql`

请求：

```json
{
  "statement": "SELECT * FROM ctl_dataset LIMIT 20"
}
```

查询响应：

```json
{
  "code": "OK",
  "data": {
    "queryId": "sql-01J...",
    "statementType": "SELECT",
    "columns": ["dataset_code", "display_name", "status"],
    "rows": [
      ["station_daily", "站点日汇总", "ACTIVE"]
    ],
    "rowCount": 1,
    "affectedRows": null,
    "truncated": false,
    "durationMs": 18
  }
}
```

写操作响应：

```json
{
  "code": "OK",
  "data": {
    "queryId": "sql-01J...",
    "statementType": "UPDATE",
    "columns": [],
    "rows": [],
    "rowCount": 0,
    "affectedRows": 3,
    "truncated": false,
    "durationMs": 11
  }
}
```

SQL 错误统一返回 HTTP 400：

```json
{
  "code": "SQL_EXECUTION_FAILED",
  "message": "SQL 执行失败",
  "details": {
    "queryId": "sql-01J...",
    "databaseMessage": "table does not exist"
  }

```

## 7. 运行方式适配

定义一个很小的接口：

```python
class DatabaseRuntime(Protocol):
    def status(self) -> str: ...
    def start(self) -> str: ...
    def stop(self) -> str: ...
    def restart(self) -> str: ...
```

第一版只实现实际要用的一种方式：

- 使用 Docker 时，实现固定容器/Compose 服务适配器。
- 使用 Windows MySQL 服务时，实现固定服务名适配器。
- 使用远程数据库或 SQLite 时，实现不可启停适配器。

不要一开始同时兼容三种启停方式。

## 8. 最低限度的保护

即使是学生项目，也保留以下低成本措施：

1. 默认只监听 `127.0.0.1`。
2. 浏览器不能输入或修改系统命令。
3. 一次只执行一条 SQL。
4. 查询最多返回 500 行。
5. SQL 失败时回滚事务。
6. 危险 SQL 在页面二次确认。
7. 所有操作进入日志。
8. 数据库密码仍通过环境变量提供，不写进 HTML、代码或 Git。

这些措施实现成本很低，但能避免最常见的误操作。

## 9. 实现顺序

1. 实现 SQL 执行器及单元测试。
2. 实现内存日志和日志查询接口。
3. 实现单页 HTML、结果表格和自动日志刷新。
4. 根据实际数据库运行方式实现一个启停适配器。
5. 增加 Flask 启动脚本并完成本机演示。

前三步不依赖最终 MySQL 环境。第四步必须先确定结果库使用 Docker、Windows 服务还是远程数据库。

## 11. 第一阶段：SQL 执行器和日志核心

### 11.1 `log_store.py`

定义：

```python
@dataclass(frozen=True, slots=True)
class ConsoleLogEntry:
    sequence: int
    time: datetime
    category: str
    level: str
    action: str
    message: str
    duration_ms: int | None = None

class ConsoleLogStore:
    def append(...) -> ConsoleLogEntry: ...
    def list(self, *, after: int = 0, limit: int = 200) -> tuple[ConsoleLogEntry, ...]: ...
    @property
    def last_sequence(self) -> int: ...
```

实现约束：

- 使用 `deque(maxlen=500)`。
- 使用 `threading.Lock` 保护序号和队列。
- `after` 为日志序号，不使用数组下标。
- `limit` 强制限制在 1～500。

### 11.2 `sql_executor.py`

定义：

```python
@dataclass(frozen=True, slots=True)
class SqlExecutionResult:
    query_id: str
    statement_type: str
    columns: tuple[str, ...]
    rows: tuple[tuple[object, ...], ...]
    row_count: int
    affected_rows: int | None
    truncated: bool
    duration_ms: int

class SqlExecutor:
    def __init__(self, connection_factory, log_store, *, max_rows: int = 500): ...
    def execute(self, statement: str) -> SqlExecutionResult: ...
```

执行逻辑：

1. 拒绝空 SQL。
2. 打开一个新数据库连接和游标。
3. 执行用户提供的一条 SQL。
4. 如果 `cursor.description` 存在，则读取最多 `max_rows + 1` 行，用额外一行判断是否截断。
5. 如果没有结果集，则提交事务并返回 `rowcount`。
6. 出现异常时回滚事务，记录错误日志，然后抛出 `SqlExecutionError`。
7. 无论成功失败都关闭游标和连接。

语句类型仅用于展示，从第一个 SQL 关键字提取；是否返回结果以 `cursor.description` 为准，不依赖手写 SQL 类型表。

### 11.3 第一阶段测试

- `SELECT` 返回列名和行。
- `CREATE/INSERT/UPDATE/DELETE` 提交事务并返回影响行数。
- SQL 错误回滚，后续连接看不到失败事务。
- 返回超过 500 行时截断并设置 `truncated=true`。
- 日期、时间、Decimal 和 `None` 能转为 JSON。
- 每次成功或失败都产生一条日志。
- 日志超过 500 条时只保留最新记录。
- `after` 能正确获取增量日志。

## 12. 第二阶段：连接、状态、启停和 HTTP API

### 12.1 `connections.py`

提供：

```python
def connection_factory_from_url(database_url: str) -> Callable[[], object]: ...
```

第一版支持：

- `sqlite:///relative/path.db`
- `sqlite:////absolute/path.db`
- `mysql+pymysql://<user>:<password>@<host>:3306/<database>`

连接 URL 只从 `NCS_DATABASE_URL` 读取，不返回给页面，也不写入日志。

### 12.2 `runtime.py`

定义：

```python
class DatabaseRuntime(Protocol):
    @property
    def mode(self) -> str: ...
    @property
    def start_stop_supported(self) -> bool: ...
    def status(self) -> str: ...
    def start(self) -> str: ...
    def stop(self) -> str: ...
    def restart(self) -> str: ...
```

实现两个适配器：

1. `UnmanagedDatabaseRuntime`：用于 SQLite、远程 MySQL 和共享 MySQL；状态为 `UNKNOWN`，启停返回 `DB_RUNTIME_NOT_MANAGED`。
2. `WindowsServiceDatabaseRuntime`：只调用固定参数形式的 `sc.exe query/start/stop <service_name>`，服务名来自后端配置，浏览器不能修改。

Windows 服务适配器要求：

- 使用参数数组调用子进程，不拼接 Shell 命令字符串。
- 单次命令超时 15 秒。
- 启停后循环检查状态，最长等待 20 秒。
- 服务不存在、权限不足和超时返回不同错误。
- 测试通过注入命令执行函数完成，不实际启停开发机服务。

### 12.3 `app.py`

应用工厂：

```python
def create_app(
    settings=None,
    *,
    connection_factory=None,
    runtime=None,
    log_store=None,
) -> Flask: ...
```

实现四个接口：

- `GET /internal/db-console/status`
- `POST /internal/db-console/runtime`
- `POST /internal/db-console/sql`
- `GET /internal/db-console/logs`

状态接口分别返回运行状态和实际连接状态。连接检查执行 `SELECT 1`，失败时返回 `DISCONNECTED`，但接口本身仍返回可展示的状态对象。

### 12.4 第二阶段配置

在 `Settings` 和 `.env.example` 增加非敏感配置名：

```text
NCS_DB_CONSOLE_HOST=127.0.0.1
NCS_DB_CONSOLE_PORT=5002
NCS_DB_CONSOLE_MAX_ROWS=500
NCS_DATABASE_CONNECT_TIMEOUT=5
```

数据库 URL 必须使用虚拟机 IP，不能使用 `localhost` 或回环地址。连接超时限制用于在虚拟机离线、网络错误或端口未开放时快速反馈。

## 14. 错误码

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `DB_CONSOLE_NOT_CONFIGURED` | 503 | 没有数据库连接配置 |
| `DB_CONNECTION_FAILED` | 503 | 无法连接数据库 |
| `DB_RUNTIME_NOT_MANAGED` | 409 | 当前数据库不能由本工具启停 |
| `DB_RUNTIME_ACTION_INVALID` | 400 | 启停动作不支持 |
| `DB_RUNTIME_PERMISSION_DENIED` | 403 | 操作系统拒绝启停服务 |
| `DB_RUNTIME_TIMEOUT` | 504 | 启停等待超时 |
| `SQL_STATEMENT_REQUIRED` | 400 | SQL 为空 |
| `SQL_EXECUTION_FAILED` | 400 | 数据库拒绝或执行 SQL 失败 |
| `SQL_RESULT_SERIALIZATION_FAILED` | 500 | 结果值无法转换为 JSON |

|---|---|---|---|
| A | SQL 执行器、事务、结果限制、内存日志 | 无 | 核心单元测试通过 |
| B | 连接工厂、状态/启停适配器、四个 API | 仅需确认实际 MySQL URL 格式 | API 测试通过 |
| C | HTML/CSS/JS、启动脚本、使用说明 | 无 | 本机页面可操作 SQLite |
| D | 实际 MySQL 启停联调 | MySQL 服务名、管理员权限 | 页面按钮控制专用 MySQL |

前三个批次可以立即完成。批次 D 必须先确认：结果库 MySQL 是否独立、运行在哪台机器、Windows 服务名是什么。若数据库为共享或远程实例，批次 D 改为“只展示连接状态”。

## 16. 完成定义

满足以下条件后，简易管理窗口视为完成：

1. 浏览器能执行 SQL 并以表格显示查询结果。
2. 写 SQL 正确提交，失败 SQL 正确回滚。
3. 页面能看到本次启动以来的 SQL 和数据库操作日志。
4. 数据库离线时页面仍能打开并显示断开状态。
5. 受管理的专用 MySQL 能从页面启动、停止和重启；不受管理的数据库明确提示不可操作。
6. 页面默认只监听本机地址。
7. 全量自动化测试通过，现有管理后端和查询后端行为不变。
