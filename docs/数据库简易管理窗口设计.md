# 数据库简易管理窗口设计

> 状态：当前建议方案
>
> 目标：以最低成本提供日志查看、SQL 执行和数据库启停能力
>
> 使用范围：学生实践、本机或受控测试环境，不作为生产数据库管理器

## 1. 方案结论

当前可以做这个 UI，但只做一个 Flask 单页工具，不建立独立 Vue/React 项目。

页面只保留三个功能：

1. 查看数据库状态，并执行启动、停止、重启。
2. 输入并执行一条 SQL，显示结果或影响行数。
3. 查看本工具产生的数据库操作日志。

不实现用户、角色、审批、监控图表、Schema 设计器、备份中心等功能。这样既满足实践演示，也不会让管理窗口本身超过结果库后端的工作量。

## 2. 一个必须明确的限制

SQLite 是嵌入式数据库，没有可启动或停止的服务。启停按钮只对 MySQL 有意义。

最新版上游交接材料中的 MySQL 还承担 Hive 元数据存储。如果结果库和 Hive 共用该 MySQL，管理页面不能停止整个 MySQL 服务，否则会同时中断 Hive。建议给结果库使用独立的本机 MySQL 或独立 Docker 容器，例如固定服务名 `ncs-result-db`。

因此采用以下规则：

- 独立 Docker MySQL：显示并启用“启动、停止、重启”。
- 独立本机 MySQL 服务：确认服务名和权限后启用。
- 远程或与 Hive 共用的 MySQL：只显示连接状态，隐藏启停按钮。
- SQLite：显示“嵌入式数据库，无需启停”。

## 3. 最小 UI

页面使用 Flask 模板、原生 CSS 和少量 JavaScript，不需要 Node.js 构建。

│ │ SELECT * FROM ctl_dataset LIMIT 20;                     │ │

## 4. 页面行为

### 4.1 数据库状态和启停

- 页面加载时获取数据库状态。
- 点击启动、停止或重启后，按钮进入等待状态。
- 后端执行固定的运行方式，不接收用户输入的系统命令。
- 操作完成后再次测试数据库连接，以实际连接结果作为最终状态。
- 停止和重启弹出一次简单确认。

### 4.2 SQL 输入框

- 一次只执行一条 SQL。
- `SELECT`、`SHOW`、`DESCRIBE` 返回表格。
- `INSERT`、`UPDATE`、`DELETE` 和 DDL 成功后提交事务并返回影响行数。
- 执行失败自动回滚并显示数据库错误。
- 查询结果最多显示 500 行，避免浏览器卡死。
- 输入框支持 `Ctrl+Enter` 执行。
- 页面检测到 `DROP`、`TRUNCATE` 或不带 `WHERE` 的 `DELETE` 时要求再次确认；后端仍以数据库事务结果为准。

这是直接 SQL 工具，因此只允许监听 `127.0.0.1` 或在可信局域网内临时运行。不要将该页面直接暴露到公网。

### 4.3 日志窗口

日志只记录这个管理工具执行的操作：

- SQL 执行时间、是否成功、耗时、返回/影响行数和错误摘要。
- 数据库启动、停止、重启和状态检查。
- 工具启动和数据库连接失败。

首版由浏览器每 2 秒拉取一次最近日志，不实现 WebSocket。后端保留最近 500 条内存日志，同时写入普通日志文件，程序重启后仍能查看历史文件。

## 5. 后端结构

```text
浏览器单页
  └─ Flask db_console Blueprint
       ├─ SqlExecutor          执行 SQL 和事务
       ├─ DatabaseRuntime      查询状态、启停数据库
       └─ ConsoleLogStore      保存最近操作日志
             │
             └─ MySQL / SQLite
```

建议目录：

```text
src/ncs_backend/db_console/
├── __init__.py
├── app.py
├── runtime.py
├── sql_executor.py
├── log_store.py
├── templates/db_console.html
└── static/db_console.css

scripts/run_db_console.py
```

管理窗口作为独立 Flask 程序运行，不混入面向前端大屏的查询服务。

## 6. 接口合同

### 6.1 获取状态

`GET /internal/db-console/status`

```json
{
  "code": "OK",
  "data": {
    "databaseType": "mysql",
    "runtimeMode": "docker",
    "runtimeStatus": "RUNNING",
    "connectionStatus": "CONNECTED",
    "databaseName": "ncs_result",
    "startStopSupported": true,
    "checkedAt": "2026-09-14T14:00:00+08:00"
  }
}
```

状态枚举：

- `runtimeStatus`：`RUNNING`、`STOPPED`、`STARTING`、`STOPPING`、`UNKNOWN`。
- `connectionStatus`：`CONNECTED`、`DISCONNECTED`。

### 6.2 启停数据库

`POST /internal/db-console/runtime`

请求：

```json
{
  "action": "RESTART"
}
```

`action` 只允许 `START`、`STOP`、`RESTART`。浏览器不能提交服务名、程序路径或命令参数，这些值固定在后端配置中。

响应：

```json
{
  "code": "OK",
  "data": {
    "action": "RESTART",
    "runtimeStatus": "RUNNING",
    "connectionStatus": "CONNECTED",
    "durationMs": 2180
  }
}
```

不支持启停时返回：

```json
{
  "code": "DB_RUNTIME_NOT_MANAGED",
  "message": "当前数据库由外部环境管理，不能从本工具启停"
}
```

### 6.3 执行 SQL

`POST /internal/db-console/sql`

请求：

```json
{
  "statement": "SELECT * FROM ctl_dataset LIMIT 20"
}
```

查询响应：

```json
{
  "code": "OK",
  "data": {
    "queryId": "sql-01J...",
    "statementType": "SELECT",
    "columns": ["dataset_code", "display_name", "status"],
    "rows": [
      ["station_daily", "站点日汇总", "ACTIVE"]
    ],
    "rowCount": 1,
    "affectedRows": null,
    "truncated": false,
    "durationMs": 18
  }
}
```

写操作响应：

```json
{
  "code": "OK",
  "data": {
    "queryId": "sql-01J...",
    "statementType": "UPDATE",
    "columns": [],
    "rows": [],
    "rowCount": 0,
    "affectedRows": 3,
    "truncated": false,
    "durationMs": 11
  }
}
```

SQL 错误统一返回 HTTP 400：

```json
{
  "code": "SQL_EXECUTION_FAILED",
  "message": "SQL 执行失败",
  "details": {
    "queryId": "sql-01J...",
    "databaseMessage": "table does not exist"
  }
}
```

### 6.4 获取日志

`GET /internal/db-console/logs?after=120&limit=200`

```json
{
  "code": "OK",
  "data": {
    "items": [
      {
        "sequence": 121,
        "time": "2026-09-14T14:03:21+08:00",
        "category": "SQL",
        "level": "INFO",
        "action": "SELECT",
        "message": "执行成功，返回 6 行",
        "durationMs": 18
      }
    ],
    "lastSequence": 121
  }
}
```

## 7. 运行方式适配

定义一个很小的接口：

```python
class DatabaseRuntime(Protocol):
    def status(self) -> str: ...
    def start(self) -> str: ...
    def stop(self) -> str: ...
    def restart(self) -> str: ...
```

第一版只实现实际要用的一种方式：

- 使用 Docker 时，实现固定容器/Compose 服务适配器。
- 使用 Windows MySQL 服务时，实现固定服务名适配器。
- 使用远程数据库或 SQLite 时，实现不可启停适配器。

不要一开始同时兼容三种启停方式。

## 8. 最低限度的保护

即使是学生项目，也保留以下低成本措施：

1. 默认只监听 `127.0.0.1`。
2. 浏览器不能输入或修改系统命令。
3. 一次只执行一条 SQL。
4. 查询最多返回 500 行。
5. SQL 失败时回滚事务。
6. 危险 SQL 在页面二次确认。
7. 所有操作进入日志。
8. 数据库密码仍通过环境变量提供，不写进 HTML、代码或 Git。

这些措施实现成本很低，但能避免最常见的误操作。

## 9. 实现顺序

1. 实现 SQL 执行器及单元测试。
2. 实现内存日志和日志查询接口。
3. 实现单页 HTML、结果表格和自动日志刷新。
4. 根据实际数据库运行方式实现一个启停适配器。
5. 增加 Flask 启动脚本并完成本机演示。

前三步不依赖最终 MySQL 环境。第四步必须先确定结果库使用 Docker、Windows 服务还是远程数据库。
