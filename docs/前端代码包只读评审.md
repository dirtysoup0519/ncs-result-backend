# 前端代码包只读评审与后端联调约束

> 资料来源：`ncs-dashboard.zip`
> 核验日期：2026-09-14
> 约束：前端代码只读，严禁在本仓库解压、复制或修改

## 1. 结论

前端 `ncs-dashboard-v3-5` 版本为 `0.3.5`，API 路径与当前后端冻结合同基本一致，可以在后端完成 ADS v2.3 和双模式基本功能后直接联调。后端必须适配已经存在的前端协议，不要求前端为我们的内部表结构或部署模式做修改。

前端包当前使用 Vue 3.5.12、Vite 5.4、Axios 1.7 和 ECharts 5.5。`package.json` 未发现 DataV 依赖，也没有 Node.js `engines >=23` 限制；这是前端实训验收缺口，由前端负责人处理。本仓库只记录问题，不修改前端 ZIP。

## 2. 运行配置

| 配置 | 当前默认 | 联调要求 |
| --- | --- | --- |
| `VITE_USE_MOCK` | `true` | 基本功能完成后改为 `false` |
| `VITE_DEMO_DATA` | `true` | 真实 API 联调时关闭 |
| `VITE_API_BASE_URL` | `/api/v1` | 保持不变 |
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:5000` | Windows Flask 运行在 5000 时保持不变 |
| Axios timeout | 10 秒 | 后端普通查询应在该时间内完成 |

开发联调使用 Vite 代理，因此浏览器访问前端 5173，前端服务器把 `/api` 转发到 Windows Flask 5000。MySQL 和数据管理程序运行位置对前端透明。

## 3. 前端固定请求

### 启动元数据

- `GET /api/v1/meta/capabilities`
- `GET /api/v1/meta/filter-options?topic=...`
- `GET /api/v1/dashboard/manifest`

### 大屏数据

- `GET /api/v1/meta/data-status`
- `GET /api/v1/dashboard/overview`
- `GET /api/v1/audience/platform-distribution`
- `GET /api/v1/charging/duration-distribution`
- `GET /api/v1/charging/weekday-weekend`
- `GET /api/v1/predictions/load`
- `GET /api/v1/charging/station-hour-heatmap?metric=kwh&limit=8`
- `GET /api/v1/stations/ranking?metric=fees&limit=10`
- `GET /api/v1/revenue/trend?granularity=MONTH`
- `GET /api/v1/charging/process-summary`

以上路径不得因双模式、ADS 版本或 MySQL 版本改变。部署差异只能发生在后端适配层。

## 4. 后端必须满足的行为

- 外层响应保持 `code/message/data/meta`。
- `capabilities.available` 与 `manifest.available` 必须一致。
- 不可用组件返回合同规定的 `UNAVAILABLE`，不能返回演示假数据。
- 预测当前可选，缺失时返回严格的空数组、空时间和 `interval.available=false`。
- 热力图不可用时保留空 `stations/points` 和空值范围结构。
- `meta` 中继续提供数据版本、业务日期和新鲜度语义。
- 金额、电量、比例、日期和小时类型必须符合已有前端 adapter 的严格校验。
- 后端不能把物理表名、Windows 路径、HDFS 路径或完整数据库连接串返回前端。

## 5. 双模式对前端的影响

前端不感知 `windows_remote` 与 `co_located_vm`：

```text
Windows 输入或虚拟机就地输入
  -> 相同批次/发布逻辑
  -> 相同 api_v1_* 视图
  -> 相同 Windows Flask DTO
  -> 不变的前端 API adapter
```

联调时只需保证 Windows Flask 在 `127.0.0.1:5000` 可用。数据由哪个入口导入，不允许改变响应字段、排序、单位或空值规则。

## 6. 联调前门禁

1. 虚拟机 MySQL 已退出 `skip-grants`，`ncs_analytics` 已初始化。
2. ADS v2.3 10 个数据集已导入并发布。
3. Windows Flask 使用只读账号访问虚拟机 MySQL。
4. 13 个固定请求均通过后端合同测试。
5. `capabilities`、`manifest` 和实际组件可用性一致。
6. 预测缺失不会阻断其他组件。
7. 前端负责人将 Mock/Demo 切换为关闭后再开始真实联调。

## 7. 需要前端负责人自行确认

- 使用 Node.js 23 及以上完成安装、校验和构建。
- 按实训要求引入或证明 DataV 的实际使用；当前包只发现 ECharts。
- 不把 `node_modules` 作为正式源码交付物，后续由锁文件重建依赖。
- 确认 ZIP 内部分中文注释/示例文件的编码，避免其他机器显示乱码。

这些事项不阻塞后端基本功能实现，但会阻塞最终实训环境验收。
