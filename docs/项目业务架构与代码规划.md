# 项目业务、架构与代码规划

> 状态：当前统一基线
> 日期：2026-09-15
> 优先级：本文、`当前范围决策.md`、`项目当前状态与下一步.md` 高于历史规划

## 1. 当前业务

本仓库接收上游已经完成清洗和分析的 ADS 结果，负责：

1. 读取 Windows 交接包、虚拟机目录或 HDFS 中的已完成 ADS 批次。
2. 校验 Schema、Manifest、文件哈希、行数、主键和跨表指标。
3. 将合格数据导入虚拟机 MySQL 的 staging/结果表。
4. 管理批次、质量检查、发布、回滚和审计。
5. 通过稳定只读视图和 Flask API 向大屏提供数据。
6. 支持 Windows 数据库工具查看连接状态、执行受控 SQL 和查看日志。

本仓库不负责 ODS/DWD/DWS/ADS 的清洗分析，不重新实现上游 Spark SQL，也不负责 Vue 页面。机器学习边界为“外部训练、本项目推理”：不训练、不调参、不评估模型效果；接收模型同学交付的结构和权重，使用已发布 `load_hourly` 生成预测并发布给前端。

“在上游虚拟机直接处理”仅表示数据管理程序就地读取 ADS/HDFS、校验并入结果库，不表示本仓库接管上游数仓计算。

## 2. 当前系统结构

```text
上游虚拟机
├─ Hadoop 3.x / HDFS
├─ Spark SQL / PySpark
├─ ADS v2.5 输出
└─ MySQL 结果库
        ▲                 ▲
        │                 │
模式 B：虚拟机 data-admin  模式 A：Windows data-admin
读取本地目录/HDFS          读取 Windows 目录/ZIP
写 127.0.0.1              写 VM-IP:3306
        │                 │
        └──────统一批次与发布逻辑──────┘

虚拟机 MySQL api_v1_* 视图
  -> Windows Flask query API
  -> Node.js 23+ / Vue 3 / DataV
```

### 固定边界

- MySQL 固定运行在虚拟机。
- 查询 API 固定在 Windows，通过虚拟机 IP 只读查询。
- 数据管理程序可在 Windows 或虚拟机运行。
- 数据库管理窗口在 Windows，不远程启停虚拟机 MySQL。
- 两种导入位置共用相同数据合同和应用服务。

## 3. 内部代码结构

```text
DeliverySource
  -> DeliveryMaterializer
  -> PackageValidator
  -> AdsVersionAdapter
  -> ImportApplicationService
  -> MySqlResultRepository
  -> api_v1_* views
  -> DashboardQueryRepository
  -> Flask API
```

| 模块 | 职责 | 不允许承担 |
| --- | --- | --- |
| `DeliverySource` | 发现并读取目录、ZIP、虚拟机文件或 HDFS | 指标计算、SQL 导入 |
| `DeliveryMaterializer` | 安全解包/物化为统一只读批次目录 | 修改上游文件 |
| `PackageValidator` | 校验 Manifest、Schema、哈希、主键和对账 | 猜测缺失口径 |
| `AdsVersionAdapter` | 按版本做显式字段映射 | 依赖部署位置 |
| `ImportApplicationService` | staging、质量、幂等、发布、回滚 | 暴露任意 SQL |
| `MySqlResultRepository` | 隔离 MySQL 方言和事务 | 返回前端 DTO |
| `DashboardQueryRepository` | 只读稳定视图 | 查询物理结果表 |
| Flask API | 参数、DTO、错误码和能力发现 | 重新计算 ADS 指标 |

## 4. 数据库结构

```text
ADS v2.5
  -> stg_* 临时导入层
  -> ctl_* 批次/质量/发布/审计
  -> rpt_* 结果表
  -> api_v1_* 稳定视图
  -> Flask DTO
```

- 当前实训环境固定让 MySQL 5.7.35 运行在 `skip-grant-tables` 恢复模式。
- 建库、迁移、导入、查询和 Shell 同步统一使用无密码 root 连接。
- 不创建 `ncs_ads_migrator`、`ncs_ads_admin`、`ncs_ads_reader`，不执行授权和越权验收。
- `api_v1_*` 视图继续作为结果表与 Flask DTO 之间的结构合同，但不是安全权限边界。
- Windows 使用 `mysql+pymysql://root@<vm-ip>:3306/ncs_analytics`；虚拟机使用 `mysql+pymysql://root@127.0.0.1:3306/ncs_analytics`。

该方案只适用于隔离的 VMware 学生实训网络。未来进入普通网络或生产环境时，必须先退出恢复模式，再恢复最小权限账号设计。

## 5. 输入模式合同

| 模式 | 程序位置 | 输入 | 数据库地址 |
| --- | --- | --- | --- |
| `windows_remote` | Windows | Windows 目录/ZIP | 虚拟机 IP |
| `co_located_vm` | 虚拟机 | 本地目录/HDFS | `127.0.0.1` 或虚拟机本机地址 |

部署模式必须显式配置，不能根据数据库地址自动猜测。相同 `sourceBatchId + manifestChecksum` 在两个入口重复提交时只能产生一次有效发布。

## 8. 代码实施规划

### P0：虚拟机数据库就绪（已完成基础项）

1. 已确认 MySQL 处于 `skip-grant-tables` 恢复模式并可从 Windows/虚拟机连接。
2. 已创建 `ncs_analytics`。
3. 虚拟机本地和 Windows 来源统一使用 root 无密码连接；不创建项目账号。
4. 已验证 MySQL 5.7.35 的迁移兼容性；字符集、时区和 SQL mode 仍需作为部署记录补齐。

基础建库和账号阶段已执行；后续权限收紧或 root 账号加固仍需单独变更记录。

### P1：双运行位置基础

1. 增加 `NCS_DEPLOYMENT_MODE`。
2. 按模式校验回环/远程数据库地址。
3. 增加连接目标脱敏信息和连接超时。
4. 数据库窗口固定为连接/SQL/日志，不控制虚拟机服务。

### P2：统一输入源

1. 定义 `DeliverySource` 和 `DeliveryMaterializer`。
2. 接入 Windows 目录、安全 ZIP、虚拟机目录。
3. 增加允许根目录、路径逃逸、文件稳定性和大小限制。
4. v2.5 定位 `contract_v2/manifest.json`，读取 Manifest 声明的 18 个 CSV，不执行包内 SQL；模型包单独从 `data_exchange/models/` 受控加载。

### P3：ADS v2.3/v2.5（已完成，被 v2.5 取代）

1. 包合同已版本化：`specs_for_schema_version` 按 Manifest 版本选择合同（2.0/2.1 → 10 个数据集，2.2+ → 18 个数据集）。
2. v2.5 新增结果表（站点维表、站点日报、日期热力图、连续负荷、Top10 快照、月度营收、KPI 环比等）迁移与导入已完成。
3. 显式转换保留百分比换算、时间质量与填充质量检查；跨文件对账（订单数、占比和）已实现。
4. 现有 API 通过 `capabilities` 兼容；按 2026-09-15 数据口径，v2.3 不再单独投入，主线为 v2.5。

### P4：HDFS 与虚拟机就地处理

1. 实现 HDFS 只读来源或受控物化适配器。
2. 只读取 SUCCESS 且已经稳定的 Spark 输出。
3. 保证 HDFS 与文件目录产生相同校验摘要。

### P5：MySQL 5.7 兼容与双入口验收（已完成基础验收）

1. 在 MySQL 5.7.35 验证迁移、索引、视图和权限 SQL。
2. Windows 导入一次，再在虚拟机提交同批次，验证不重复发布。
3. 验证失败回滚、旧发布可读和恢复模式下的重复提交幂等。
4. Windows Flask 完成全部非模型 API 冒烟测试。
5. 两个入口必须得到相同的文件摘要、行数和关键业务对账值；同批次第二次提交不得重复发布。

### P6：答辩验收（进行中：文档与验收工具已就绪）

1. Python 固定为 3.11 或 3.12。
2. 保存 Hadoop/Spark/Node/Vue/DataV/MySQL 版本与运行日志。
3. 前端展示至少八个维度和至少两组对比分析。
4. 保存关键总量、行数、哈希、API 和页面证据。

## 9. 前端只读联调约束

前端代码包不得由本仓库修改。后端完成基本功能后，严格按照其现有 `/api/v1` 请求和 adapter 合同联调；完整评审见 `前端代码包只读评审.md`。

当前前端默认启用 Mock 和 Demo，真实联调前由前端负责人关闭。当前包未发现 DataV 依赖和 Node.js 23 的 `engines` 约束，这两项由前端负责人补齐或提供验收证据，不改变后端实现范围。

- MySQL 处于当前实训约定的 `skip-grant-tables`，且未启用 `skip-networking`。
- `ncs_analytics` 存在并完成迁移。
- Windows 与虚拟机 root 连接均通过。
- v2.5 首次导入、重复导入、失败回滚通过。
- Windows 与虚拟机入口结果一致。
- Windows Flask 查询全部必需视图成功。
- 默认测试和 MySQL 环境测试通过。
