# 前端联调交接说明

> 当前结构：MySQL 位于虚拟机，Windows Flask 对外提供查询 API；完整部署说明见 `项目业务架构与代码规划.md`。

> 目标：让前端同学调试大屏接口，同时不接触 MySQL 高权限账号和项目维护者的本机密码。

前端验收环境固定为 Node.js 23 及以上、Vue 3 和 DataV。至少展示两组维度对比，建议使用“工作日 vs 周末”和“不同平台”，并组合 KPI、环图、柱图、折线/面积图、雷达图、热力图和排行条形图，避免全部使用同一种图表。

## 1. 账号边界

前端只调用 `analytics-query-api`，不直连 MySQL。不得向前端提供 root、`ncs_ads_migrator` 或 `ncs_ads_admin` 的密码。

如果前端同学在自己的电脑运行后端，只配置他本机的 `ncs_ads_reader` 只读账号。浏览器使用的开发 API Key 与数据库密码不是同一凭据；API Key 只能保护只读 HTTP 接口，不能获得数据库访问能力。

管理 API 和数据库窗口始终默认绑定 `127.0.0.1`，不作为前端接口开放。

## 2. 本地配置

复制 `config/handoff.example` 为 `.local/ncs.env`，再填写本机值：

```text
NCS_DATABASE_URL=mysql+pymysql://ncs_ads_reader:<reader-password>@<vm-ip>:3306/ncs_analytics
NCS_QUERY_HOST=127.0.0.1
NCS_QUERY_PORT=5000
NCS_QUERY_API_KEY=<random-development-api-key>
NCS_CORS_ORIGINS=http://localhost:5173
```

`.local/` 已被 Git 忽略。启动脚本自动读取 `.local/ncs.env`，但现有进程环境变量优先，不会被本地文件覆盖。

如果后端和前端不在同一台电脑，后端可以临时设置 `NCS_QUERY_HOST=0.0.0.0`，并将前端实际 Origin 加入 `NCS_CORS_ORIGINS`。此时还应使用系统防火墙限制 5000 端口只允许可信局域网设备访问。

## 3. 前端请求

配置 API Key 后，前端所有 `/api/v1/*` 请求任选一种方式携带：

```http
X-API-Key: <random-development-api-key>
```

或：

```http
Authorization: Bearer <random-development-api-key>
```

未配置 `NCS_QUERY_API_KEY` 时保持本地开发兼容，不要求认证。存在浏览器 `Origin` 时必须位于 `NCS_CORS_ORIGINS` 中；无 Origin 的本机脚本请求不受 CORS 限制。

## 4. 启动与检查

```powershell
python scripts/run_query.py
```

前端先检查：

```text
GET /health/live
GET /health/ready
GET /api/v1/meta/capabilities
GET /api/v1/dashboard/manifest
```

`health` 接口不要求 API Key，业务接口要求。

## 5. 安全打包

确保工作区已经提交并且没有未提交改动，然后运行：

```powershell
python scripts/package_frontend_handoff.py
```

脚本使用当前 Git `HEAD` 创建 `dist/ncs-frontend-handoff.zip`，因此不会包含 `.local/`、`.env`、缓存、本地数据库和未跟踪文件；生成后还会再次检查常见密钥和数据库文件类型。

不要直接压缩整个工作目录。直接压缩可能把被 Git 忽略的本地配置、数据库文件和缓存一起发送出去。
