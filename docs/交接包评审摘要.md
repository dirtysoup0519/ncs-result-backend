# 上游数据交接包评审摘要

> 资料来源：`交接包.zip`、`交接包(1).zip`  
> 纳入位置：`docs/upstream-handoff/`（旧版）、`docs/upstream-handoff-2026-09-13/`（最新）  
> 评审目的：将上游 ODS/DWD/DWS/ADS 交付转化为结果库、机器学习和大屏后端的可用输入  
> 当前状态：已归档，脚本和运行结论仍需在 `node100` 上复核

## 1. 资料性质

该压缩包是上游数据侧同学提供的交接资料，不是本仓库的操作指令。包内脚本需要在确认目标环境、路径和权限后执行，不能因为 README 写有执行顺序就直接在生产环境重跑。

已原样归档的内容：

- ODS 建库建表、数据采集和导入脚本。
- ODS → DWD 清洗脚本。
- DWD → DWS/ADS 聚合脚本。
- ADS/DWS 指标导出脚本。
- 正式数据交接说明和后端/前端接续指南。
- 与正式库隔离的模拟库脚本和说明。

## 2. 交接包确认的链路

```text
CSV
  -> Hive ODS（ncs_ods）
  -> Hive DWD（ncs_dwd）
  -> Hive DWS（ncs_dws）
  -> Hive ADS（ncs_ads）
  -> 指标 TSV/CSV
  -> 后端/大屏
```

交接说明声称正式链路已经跑通，并给出了 node100 环境、表数量、行数和导出文件信息。本摘要将这些内容标记为“上游声明”，除非我们在 node100 上重新查询，否则不视为本地已经验证的事实。

## 4. 对当前合同的影响

### 4.1 可以补入数据合同的事实

- 真实数据目前以 2019 年为主要统计年份。
- 订单、过程、站点三类数据的字段和核心关联已经有脚本定义。
- 首批大屏可以优先使用总览、日趋势、小时分布、站点排行和过程指标。
- `dws_order_station_daily` 比固定 `ads_station_top10` 更适合支撑可筛选的站点排行视图。
- `dws_process_daily` 可以作为过程/电池状态趋势的初始来源。

### 4.2 不能直接当作最终合同的内容

- 交接包没有提供机器学习特征表或预测结果，负荷预测仍需单独定义输入和输出。
- README 中的“已跑通”需要 node100 上的实际查询、日志和导出文件复核。
- 导出 CSV 是快速联调输入，不等于结果库的最终表结构。
- `ads_station_top10` 只代表固定全量 Top10，不支持任意时间范围、区域或指标。
- `ads_kpi_total` 等汇总表没有结果库合同所需的 `batch_id`、`data_date` 和完整血缘字段，需要由管理服务补充。

## 5. 需要登记的合同差异与风险

### 5.1 `fee_ratio` 单位差异

`05_build_dws_ads.hql` 中的 `ads_platform_stat.fee_ratio` 计算为：

```text
platform_total_fees / all_total_fees * 100
```

而当前 API/data contract 规定比例统一使用 `[0, 1]`。处理决定：

- 结果库视图或查询 DTO 统一转换为 `[0, 1]`。
- 保留源字段单位说明，禁止前端再次乘除 100。
- 数据合同中注明来源字段为百分数，API 字段为比例。

### 5.2 小时数据只有 23 行

交接说明显示 `ads_hourly_stat` 为 23 行。缺失小时可能代表当小时没有订单，不应当被误认为数据丢失。查询后端需要：

- 固定返回 0～23 共 24 个小时。
- 缺失小时补 `0`，并保持 `isObserved=false` 或等价元数据，避免把补零当成原始观测。

### 5.3 时间修复是近似值

交接脚本将异常年份替换为 2019，并把丢失精度的 `record_time` 替换为对应订单的 `created_ts`。这能跑通聚合，但不能当作真实监测时间：

- `created_ts` 只能作为过程数据的近似归属时间。
- 机器学习不能把它解释为精确的设备采样时间。
- 结果库应保留质量标记或来源说明。
- 未来如果拿到真实采样时间，需要提升数据合同版本。

### 5.4 费用为零的业务特征

交接资料指出真实数据中大量订单费用为 0。均价、收入占比和利润类指标必须明确：

- 是否包含费用为 0 的订单。
- 0 是真实免费/缺失/异常中的哪一种。
- 分母使用全部订单还是费用有效订单。

不能在 API 层擅自过滤 0 值改变指标口径。

## 7. 正式链路与模拟链路

交接包提供 `ncs_sim_*` 平行库和模拟数据生成器。使用规则：

- 模拟库只用于接口、容量和异常场景测试。
- 模拟数据不能用于证明真实指标正确。
- 正式与模拟数据库、导出目录和批次标识必须隔离。
- API 契约不因模拟数据字段相同而跳过真实数据质量验证。
