> 状态：历史总体规划。当前业务、双运行位置结构和代码顺序以 `项目业务架构与代码规划.md` 为准。

> 目标分支：`feature/project-foundation`  
> 历史实现对象：`shared-kernel`、`data-admin-service`、`analytics-query-api`、`ml-pipeline`、MySQL 结果库；`ml-pipeline` 当前不实施
> 设计依据：`内部逻辑与对接设计.md`、`data-contract.md`、`api-contract.md`、`实现路线与对接清单.md`

> **当前范围覆盖说明（2026-09-14）**：本项目当前只实现处理后数据的结果库、数据管理后端和大屏查询后端。本文涉及 `ml-pipeline`、训练、推理、模型登记和预测运行管理的章节全部降级为未来可选方案，不进入当前开发与验收。上游提供的预测结果只作为普通处理后数据集管理。以 `当前范围决策.md` 为准。

## 1. 代码目标与边界

本仓库实现以下闭环：

```text
ADS 统计/特征交付
  -> data-admin-service 导入、校验、发布、回滚
  -> MySQL rpt_* 结果表和 api_v1_* 稳定视图
  -> analytics-query-api
  -> Web 大屏

ADS 特征交付
  -> ml-pipeline 训练、评估、登记、离线预测
  -> data-admin-service 校验和发布
  -> MySQL 预测结果视图
  -> analytics-query-api
```

代码不包含 ODS/DWD/DWS/ADS 生产脚本、Qt、交易业务、设备控制和前端页面。

## 2. 技术基线

首轮采用以下基线，具体版本在部署环境确认后锁定：

| 类别 | 基线 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.11+ | 三个程序统一版本 |
| Web | Flask application factory | 管理服务和查询服务独立应用 |
| 数据访问 | SQLAlchemy 2.x | 统一连接、事务和参数化查询 |
| 迁移 | Alembic | 所有表、视图和权限变更版本化 |
| 合同模型 | dataclass/枚举 + API schema 库 | 领域模型不依赖 Flask 请求上下文 |
| 数据校验 | 独立 validator 端口 | schema、粒度、唯一性、范围、对账 |
| 机器学习 | pandas + scikit-learn 适配器 | 先做可复现基线，框架可替换 |
| 测试 | pytest | 单元、合同、集成和端到端测试 |
| 接口描述 | OpenAPI | 由实现和合同测试共同校验 |
| 配置 | 环境变量 + `.env.example` | 不提交真实凭据 |

原则：业务规则依赖抽象端口，Flask、MySQL、文件格式和模型框架只是适配器。

## 4. 公共内核实现

### 4.1 值对象

首批实现：

- `DatasetCode`、`SchemaVersion`、`BatchId`、`DataDate`。
- `ModelCode`、`ModelVersion`、`PredictionHorizon`。
- `Money`、`Ratio`、`MetricValue`。
- `PageRequest`、`PageResult`。
- `TraceId`、`IdempotencyKey`。

所有值对象在构造时校验，禁止无效状态进入业务服务。例如比例的 API 表达统一为 `[0,1]`，金额使用定点数，不使用二进制浮点数。

### 4.2 状态与错误

首批状态机：

```text
import batch:
CREATED -> LOADING -> VALIDATING -> READY -> PUBLISHED
                    -> REJECTED
         -> FAILED

model version:
REGISTERED -> VALIDATED -> ACTIVE -> RETIRED
                         -> REJECTED

prediction run:
CREATED -> RUNNING -> VALIDATING -> READY -> PUBLISHED
                  -> FAILED       -> REJECTED
```

错误按域划分：`VALIDATION_*`、`DATASET_*`、`BATCH_*`、`PUBLISH_*`、`QUERY_*`、`MODEL_*`、`AUTH_*`、`DEPENDENCY_*`。

## 5. 数据库实现规划

### 5.1 控制表

优先实现与业务字段无关的控制表：

| 表 | 用途 |
| --- | --- |
| `ctl_dataset` | 数据集目录和当前 schema |
| `ctl_schema_version` | schema 内容、版本和兼容性 |
| `ctl_import_batch` | 导入批次、来源、行数和状态 |
| `ctl_quality_result` | 规则执行结果和失败明细摘要 |
| `ctl_publication` | 已发布数据版本及历史 |
| `ctl_audit_log` | 管理动作审计 |
| `ml_model_version` | 模型版本、指标、参数和制品哈希 |
| `ml_prediction_run` | 预测运行、数据版本和状态 |

### 5.2 业务结果表

字段确认后按主题逐个落地：

- `rpt_kpi_snapshot`
- `rpt_metric_daily`
- `rpt_metric_hourly`
- `rpt_station_daily`
- `rpt_station_snapshot`
- `rpt_load_prediction`

每张表必须具备完整粒度唯一键、`batch_id`、`data_date`、`schema_version`、`loaded_at` 和来源标识。最终字段以确认后的 ADS 映射为准。

### 5.3 查询视图

首批视图：

- `api_v1_data_status`
- `api_v1_kpi_overview`
- `api_v1_metric_daily`
- `api_v1_metric_hourly`
- `api_v1_platform_distribution`
- `api_v1_duration_distribution`
- `api_v1_weekday_weekend_profile`
- `api_v1_station_hour_heatmap`
- `api_v1_process_summary`
- `api_v1_station_ranking`
- `api_v1_station_list`
- `api_v1_load_prediction`

视图只暴露当前已发布版本，不暴露 staging、未通过质量校验的批次或内部审计字段。复杂聚合进入结果表，不依赖普通视图重复扫描大量数据。

当前已实现只读视图契约检查器：`query.view_contract` 仅对固定白名单执行零行元数据检查，并报告缺失列；在上游 ADS 字段和实际建视图脚本冻结前，不据此臆造物理 DDL。

### 5.4 迁移顺序

1. 控制表与基础索引。
2. 模型元数据表。
3. 第一批结果表。
4. `api_v1_*` 视图。
5. 最小权限 grant 脚本。

所有迁移必须同时验证升级路径；破坏性降级或数据删除不自动执行。

## 6. 数据库管理服务实现

### 6.1 领域模块

- `dataset_registry`：登记数据集与 schema。
- `batch_manager`：创建批次和控制状态转换。
- `import_orchestrator`：调用导入适配器写入 staging。
- `quality_service`：运行质量规则并汇总结果。
- `publication_service`：原子发布、切换可见版本和回滚。
- `model_registry`：登记、校验、启用和停用模型。
- `prediction_publication`：登记和发布预测结果。
- `audit_service`：记录管理动作。

### 6.2 端口

- `DatasetRepository`
- `BatchRepository`
- `PublicationRepository`
- `QualityResultRepository`
- `Importer`
- `QualityRule`
- `TransactionManager`
- `Clock`
- `AuditSink`

### 6.3 适配器

首轮实现本地 CSV/TSV 和 SQLAlchemy/MySQL 适配器；Sqoop 或其他正式导入方式在环境确认后新增，不改变应用服务接口。

### 6.4 管理接口优先级

P0：

- 登记/查询数据集 schema。
- 创建和查询导入批次。
- 触发校验、查询质量结果。
- 发布和回滚批次。
- 查询当前发布版本。
- 登记模型和预测运行。
- 发布预测结果。

P1：质量规则在线配置、批次取消、批量回收和审计查询。Webhook、任意调度和在线 DDL 暂不实现。

## 7. 查询后端实现

### 7.1 分层

```text
Flask route
  -> request schema
  -> query application service
  -> read-only repository port
  -> api_v1_* view adapter
  -> response DTO
```

路由不得直接写 SQL；仓储只能查询白名单视图；查询服务不得写数据库、触发导入或训练模型。

### 7.2 大屏 API 实现波次

基础接口先行：`GET /health/live`、`GET /health/ready`、`GET /api/v1/meta/capabilities`、`GET /api/v1/meta/data-status`。

前端联调按以下波次推进：

1. Wave A（P0）：`dashboard/overview`、`audience/platform-distribution`、`stations/ranking`、`revenue/trend`、`charging/process-summary`。
2. Wave B（P1）：`charging/duration-distribution`、`charging/weekday-weekend`、`charging/station-hour-heatmap`。
3. Wave C（P2）：`predictions/load`；必须等预测目标、`cutoffHour` 和发布合同冻结。
4. P3：运营建议 V1 由前端使用本地模板生成，后端只预留扩展接口，不进入首轮实现。

站点基础列表、充电小时与通用趋势继续作为复用接口实现，但不阻断前端首屏 Wave A 联调。站点榜 V1 默认 `metric=fees`；趋势只返回充电费用、充电量和可选订单数，不推断服务费、利润或收益。

具体路径和字段以 `api-contract.md` 为准，实现时若文档与代码命名冲突，先修改合同再编码。

### 7.3 后端内部规则

- 统一解析日期范围、站点筛选、指标代码、排序和分页。
- 固定补齐 0～23 小时，并返回观测标记。
- 每个响应包含数据日期、版本、新鲜度和追踪 ID。
- 不存在已发布预测时返回能力不可用或明确空结果，不回退到伪造数据。
- 支持 ETag；缓存是否启用由性能测试决定。
- 数据库失败、超时、参数错误、空数据和过期数据分别处理。

## 8. 机器学习流水线实现

### 8.1 模块

- `feature_loader`：按数据集版本读取特征。
- `time_splitter`：按时间切分训练、验证和测试集。
- `trainer`：通过模型端口训练。
- `evaluator`：计算基线与候选模型指标。
- `artifact_store`：保存制品并计算哈希。
- `model_registrar`：向管理服务登记模型。
- `predictor`：生成离线预测。
- `prediction_validator`：校验覆盖率、范围和时间连续性。

### 8.2 首个基线

在预测目标确认后，先实现可解释的朴素基线，例如相同站点上一周期或同星期时段值；随后再加入树模型适配器。没有可靠时间字段和标签时，不进入训练实现。

### 8.3 防泄漏与复现

- 只允许时间切分，不随机打散时间序列。
- 特征生成时间必须早于预测目标时间。
- 记录数据版本、代码提交、参数、随机种子、依赖版本和制品哈希。
- 指标必须按站点、时域和总体分别报告。
- 模型未超过已确认基线和阈值时不得启用。

## 9. 配置、安全与权限

配置分为 `common`、`admin`、`query`、`ml` 四组。仓库只提交变量名、默认非敏感值和说明。

数据库账号至少分为：

- `migration_user`：仅迁移时使用。
- `admin_service_user`：写控制表、staging 和结果表，不拥有任意 DDL 权限。
- `query_service_user`：仅 `SELECT api_v1_*`。
- `ml_pipeline`：默认不直接访问发布表，通过管理服务登记；如读取特征库，使用独立只读账号。

管理接口默认只在内网开放，并使用服务身份认证。日志不得记录连接串、Token、完整数据行或模型本地敏感路径。

## 13. 第一批代码的准确范围

新分支 `feature/project-foundation` 的基础实现已包含 Iteration 1～2，并新增了查询 API 的合同骨架：

- Python 项目与包结构。
- 公共标识、枚举、错误和配置模型。
- 管理服务和查询服务的应用工厂骨架。
- 机器学习 CLI 骨架。
- 存活检查、就绪检查的抽象结构。
- 最小单元测试和启动说明。
- 按 `大屏接口冻结合同_v1.md` 注册 P0/P1/P2 查询路由、参数校验、统一响应和空数据适配器。

当前明确不包含真实 MySQL 凭据、最终 ADS 字段、正式结果表、生产导入、机器学习流程和部署配置。下一步继续接入处理后数据的结果表、控制表和只读视图，不实现模型相关代码。

当前查询代码已提供 `DbApiDashboardRepository` 的 DB-API 适配骨架和 SQLite 合同测试。它只访问白名单 `api_v1_*` 视图，真实 MySQL 驱动、视图 DDL 和 ADS 字段映射仍需在 Iteration 3～4 根据上游材料接入。

控制面初始化代码已提供 `initialize_control_schema` 和本地 CLI 入口，只创建数据集、Schema、导入批次、质量、发布和审计等 `ctl_*` 表，不创建 `ml_*` 表，也不开放任意 SQL。

当前已补充 `DbApiControlRepository`、`DatasetRegistryService`、`BatchService`、`ImportPreparationService`、`ImportLoadingService`、`QualityService` 和 `PublicationService`：支持数据集目录与不可变 Schema 版本登记、上游批次与 Manifest 校验和幂等创建、规则结果幂等创建、JSON/CSV/TSV 文件读取、Manifest/Schema/校验和验证、schema-neutral staging 行写入、`CREATED -> LOADING -> VALIDATING` 加载状态转换、质量结果持久化、`BLOCKER/ERROR` 阻断校验、READY 批次原子发布、旧发布版本标记为 `SUPERSEDED`、按明确目标批次回滚以及审计记录。当前适配器使用 SQLite 的 DB-API `qmark` 参数风格，MySQL 参数和连接池适配仍需在环境确认后接入；正式 JDBC/Sqoop 导入通道和具体质量规则编排尚未实现。

管理服务 `admin.app.create_app` 已增加受控 `/internal/v1` 路由：数据集登记、批次创建/查询、质量完成、质量结果查询、发布和按明确目标批次回滚。HTTP 层只做请求解析与响应映射，实际状态、质量和发布规则仍由应用服务负责；MySQL 连接组装已经完成，鉴权中间件、幂等键持久化和 ADS v2.1 专用导入 API 尚未接入。
