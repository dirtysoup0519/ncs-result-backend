# 双运行位置数据接入设计

> 状态：双入口已实现；Windows 远程导入和虚拟机 Shell 就地同步共用同一导入内核
> 目标：同一套项目既能在 Windows 接收交接包并写入虚拟机 MySQL，也能部署到上游所在虚拟机直接处理 ADS 输出

## 1. 架构结论

项目采用“可移动的数据管理程序 + 固定的数据合同”，不把运行位置写进业务逻辑。查询后端默认运行在 Windows，MySQL 固定运行在虚拟机；数据管理程序可以运行在 Windows 或虚拟机。

```text
                         ┌─ 模式 A：Windows 输入
ADS 交接包 ──────────────┤  Windows data-admin
                         │    -> VM-IP:3306
                         │
                         └─ 模式 B：虚拟机就地处理
Spark ADS 输出 / HDFS       VM data-admin
                              -> 127.0.0.1:3306

虚拟机 MySQL api_v1_* 视图
  -> Windows Flask query API
  -> Vue 3 + DataV
```

两种模式只能改变输入适配器和数据库地址，以下逻辑必须完全复用：Manifest/Schema 校验、文件哈希、主键检查、跨表对账、字段转换、批次状态机、事务导入、发布、回滚和审计。

当前工作区上一轮形成的“所有 MySQL 回环地址一律拒绝”属于远程单模式中间实现，与本设计不兼容。实现 D1 时必须改为按 `NCS_DEPLOYMENT_MODE` 校验；在此之前不要把该中间实现作为可部署版本。

## 2. 两种运行模式

### 2.1 模式 A：Windows 输入、远程写库

适用于前端或项目成员在 Windows 收到 ZIP/解压目录后联调。

```text
Windows 文件目录
  -> DirectoryDeliverySource
  -> data-admin（Windows）
  -> MySQL（虚拟机 IP）
```

- 数据库地址必须是虚拟机可达 IP，不能是 Windows 的 `localhost`。
- Windows 负责解包、校验和导入，不能控制虚拟机 MySQL 的启停。
- ZIP 先安全解压到受控临时目录，拒绝路径穿越、符号链接逃逸和超限文件。
- 适合人工联调和临时交接，但大文件跨虚拟网络传输效率较低。

### 2.2 模式 B：虚拟机就地处理、本地写库

适用于上游 Spark 完成后，直接在同一台虚拟机运行本仓库的数据管理命令。

```text
Spark 输出目录 / HDFS
  -> DirectoryDeliverySource 或 HdfsDeliverySource
  -> data-admin（虚拟机）
  -> MySQL（127.0.0.1）
```

- 虚拟机内允许使用 `127.0.0.1`，但必须显式选择 `co_located_vm` 部署模式。
- HDFS 输入先由只读适配器列出和读取，或物化到批次临时目录；业务层不直接依赖 Hadoop 命令。
- 只接受存在 `SUCCESS` Manifest 且文件稳定的批次，避免读取 Spark 正在写入的目录。
- 该模式减少跨机数据搬运，是答辩运行的优先方案。

## 3. 配置模型

建议增加以下非敏感配置，真实密码仍通过本地环境变量注入：

```text
NCS_DEPLOYMENT_MODE=windows_remote | co_located_vm
NCS_DELIVERY_SOURCE=directory | archive | hdfs
NCS_DELIVERY_ROOT=<allowed-root-or-hdfs-uri>
NCS_DATABASE_URL=<mysql-url>
NCS_DATABASE_CONNECT_TIMEOUT=5
```

配置校验规则：

| 部署模式 | 程序位置 | MySQL 地址 | 允许输入 |
| --- | --- | --- | --- |
| `windows_remote` | Windows | 非回环虚拟机 IP/主机名 | Windows 目录、ZIP |
| `co_located_vm` | 虚拟机 | `127.0.0.1`、虚拟机本机地址 | 虚拟机目录、HDFS |

禁止根据“地址是不是 localhost”自动猜运行模式。模式必须显式配置，启动时做交叉校验；配置矛盾时立即退出并给出不含密码的错误。

## 4. 代码边界设计

```text
DeliverySource
├─ WindowsDirectorySource
├─ SafeArchiveSource
├─ VmDirectorySource
└─ HdfsDeliverySource
        │
        v
DeliveryMaterializer -> 标准只读批次目录
        │
        v
PackageValidator -> AdsVersionAdapter -> ImportApplicationService
                                           │
                                           v
                                  MySqlResultRepository
```

### `DeliverySource`

只负责发现批次、读取 Manifest 和取得文件流，不解释指标，不执行 SQL。

### `DeliveryMaterializer`

把 ZIP、Windows 目录、虚拟机目录或 HDFS 输入统一成标准只读批次目录，并计算来源 URI、大小和哈希。业务层从这一层之后不再区分 Windows/HDFS。

对于本次 ADS v2.3，物化器必须定位 `contract_v2/manifest.json`，并只暴露 Manifest 声明的 10 个 CSV。包根目录下的 SQL、说明、校验辅助文件和 `ml/` 不进入导入集合，也不得执行。

### `AdsVersionAdapter`

按 Manifest 的 Schema/version 选择 v2.1 或 v2.3 映射，完成显式字段转换。禁止用文件路径或运行位置推断版本。

### `ImportApplicationService`

统一执行 `校验 -> staging -> 质量检查 -> READY -> PUBLISHED`。两种模式使用相同幂等键：`sourceBatchId + manifestChecksum`，避免同一批次从 Windows 和虚拟机重复发布。

## 5. 管理接口设计

保留现有本地目录导入能力，并抽象为统一请求：

```json
{
  "sourceType": "directory",
  "sourceUri": "file:///data/ncs/contract_v2",
  "expectedVersion": "2.0.0",
  "publish": true
}
```

后续支持：

- `directory`：服务端允许根目录内的路径。
- `archive`：先上传/放置到受控目录，再安全解压；不允许请求体传任意宿主机路径。
- `hdfs`：使用 `hdfs:///...` URI，只允许配置前缀内的目录。

响应统一返回任务/批次 ID、来源类型、校验状态、数据集结果和发布状态，不返回数据库 URL、本机绝对敏感路径或凭据。

## 6. 并发与一致性

- 同一 `sourceBatchId + checksum` 重复请求返回既有结果。
- Windows 和虚拟机同时提交同批次时，由 MySQL 唯一约束和发布锁保证只有一个导入者。
- staging 写入和发布切换必须在事务边界内；失败保留审计，不影响旧发布。
- 输入文件校验后再次确认大小和修改时间，防止校验期间被上游覆盖。
- Spark 输出必须先写临时目录，完成后再生成 SUCCESS Manifest 或原子重命名。

## 7. 数据库与权限

- MySQL 固定在虚拟机。
- 当前实训环境固定运行在 `skip-grant-tables`，虚拟机与 Windows 统一使用无密码 root。
- 虚拟机内连接 `127.0.0.1`，Windows 连接虚拟机 IP；两种入口复用同一导入和发布逻辑。
- 不创建迁移、管理、查询账号，也不执行权限检查；`api_v1_*` 仅承担稳定结构合同。
- 数据库窗口仅显示连接、SQL 和日志，不远程启停虚拟机 MySQL。
- 该例外仅用于隔离的 VMware 实训网络；若未来恢复普通认证，必须另行设计最小权限账号和密钥管理。

## 8. 实施阶段

### D1：部署模式与连接策略（已完成）

- Windows 远程连接和虚拟机本地连接由配置显式指定，不根据地址猜模式。
- 两种模式共用导入、发布、回滚和审计逻辑。

### D2：统一输入源（已完成）

- 抽象 `DeliverySource` 和物化结果。
- 将现有目录/ZIP 入口接入统一服务。
- 新增允许根目录、文件稳定性和幂等测试。

### D3：虚拟机/HDFS 适配（Shell 基础版已完成）

- 增加虚拟机目录模式。
- 增加 HDFS 只读适配器或受控导出适配器。
- 用同一份 v2.3 数据证明 Windows 与虚拟机模式产生相同校验摘要和结果表。

当前 v3.2 `contract_v2` 双模式一致性以 Manifest checksum、18 个数据集行数、每个文件 SHA-256 和批次发布状态为准；历史 v2.3/v2.5 对账数字仅用于旧包复核。

### D4：双入口联调（已完成基础验收）

- 在虚拟机初始化结果库并验证恢复模式 root 连接。
- 分别从 Windows、虚拟机导入，验证重复批次只发布一次。
- Windows 查询 API 对两种导入来源返回相同 DTO。

## 9. 验收标准

1. Windows 可以使用虚拟机 IP 导入 v2.5 并查询结果。
2. 同一仓库部署到虚拟机后，可以读取本地 ADS 目录或 HDFS 并写入本机 MySQL。
3. 两种模式共享全部业务逻辑，结果摘要、对账值和 API DTO 一致。
4. 同一批次跨模式重复导入不会产生重复发布。
5. Windows 查询后端在导入程序运行位置变化后无需修改接口合同。
6. 凭据不进入仓库，日志和响应不输出密码或完整连接串。
