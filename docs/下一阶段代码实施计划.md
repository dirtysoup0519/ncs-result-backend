## 3. 阶段 N1：本地开发库落地

状态：已完成。本地开发库默认位于 `.local/ncs.sqlite`，由统一命令幂等初始化且不进入 Git。

### 目标

建立一个可重复创建的本地开发数据库，验证当前控制面和数据库窗口可以实际运行。该数据库只用于开发，不代表正式业务结果库。

### 代码任务

1. 增加统一的开发库初始化入口：
   - 创建目标目录。
   - 初始化 `ctl_*` 控制表和 `stg_import_row`。
   - 重复执行不报错、不重复创建版本记录。
   - 输出数据库位置、迁移版本和表清单。
2. 增加数据库结构检查命令：
   - 检查必需表是否存在。
   - 检查当前迁移版本。
   - 失败时返回非零退出码和稳定错误信息。
3. 补充本地运行说明：
   - 初始化开发库。
   - 启动管理 API、查询 API 和数据库窗口。
   - 不在仓库提交生成的 `.sqlite` 文件。
4. 增加集成测试：
   - 空目录首次初始化。
   - 同一路径重复初始化。
   - 已存在不完整结构时给出明确结果。
   - 管理窗口连接初始化后的数据库并执行只读查询。

### 计划文件

```text

src/ncs_backend/admin/migrations.py

```

### 验收

- 一条命令可以建立本地开发库。
- 初始化两次得到相同结构。
- 管理窗口能够显示连接成功并查询控制表。
- 全量测试通过，生成数据库不进入 Git。

### 外部依赖

无，不需要 ADS。

## 4. 阶段 N2：数据库适配边界收紧

状态：已完成。SQLite 全量测试和 MySQL 8.0.46 真实环境迁移、查询、回滚及权限验证均已通过。

### 目标

让 SQLite 开发环境与未来 MySQL 环境共用应用逻辑，把数据库差异限制在连接、参数占位符和迁移适配层。

### 代码任务

1. 建立明确的数据库方言接口：
   - 参数占位符转换。
   - 事务开始、提交和回滚。
   - 表和视图存在性检查。
   - 日期时间与 JSON 字段序列化边界。
2. 移除仓储中对 SQLite `?` 占位符的隐式依赖，由适配器生成对应 SQL。
3. 为 MySQL 迁移准备独立 DDL，不直接把 SQLite DDL 字符串替换后执行。
4. 增加 SQLite 合同测试；MySQL 测试标记为环境测试，在取得本地 MySQL 后启用。
5. 配置只从环境变量读取，连接串和密码不写入日志、页面或 Git。

### 计划目录

```text

  sqlite.py
  mysql.py
src/ncs_backend/admin/migrations/
  sqlite/
  mysql/

```

实际拆目录时保持现有公共接口兼容，避免一次性重写管理服务。

### 验收

- 相同仓储测试可在 SQLite 和 MySQL 适配器下运行。
- SQL 参数始终绑定，不拼接用户值。
- MySQL 不可用时不影响默认测试套件。
- MySQL 环境测试具备明确的启用条件，不使用仓库内凭据。

### 外部依赖

- SQLite 部分无外部依赖，可以立即完成。
- MySQL 实测需要环境负责人提供版本、地址、库、账号权限和字符集；缺失时只完成接口与测试夹具，不声称 MySQL 已验收。

## 6. ADS 接入门禁

阶段 N1～N3 已完成。ADS v2.1 联调包已提供表结构、样例、行数、字段数、文件哈希和基础对账，可以启动联调级业务代码；以下材料中仍缺失的部分继续作为最终合同门禁：

| 材料 | 最低要求 | 缺失影响 |
| --- | --- | --- |
| ADS DDL | 表名、字段、类型、注释、分区 | 无法设计结果表和导入映射 |
| 脱敏样例 | 每表至少 20 行，包含零值、空值和边界值 | 无法编写可靠的 Schema 与质量测试 |
| 一行粒度 | 每张表的一行代表什么、候选唯一键 | 无法建立唯一约束和幂等导入 |
| 指标口径 | 公式、过滤条件、单位、精度、零值和空值规则 | 无法保证前后端数值语义一致 |
| 时间口径 | 时区、数据日期、修复字段和逻辑星期来源 | 无法安全聚合或按日期查询 |
| ID 映射 | `station_id` 等标识来源和关联覆盖率 | 无法保证站点排行、筛选和热力图关联 |
| 刷新与批次 | 全量/增量、刷新频率、批次 ID 和重跑规则 | 无法实现发布、新鲜度和回滚 |
| 对账基准 | 每批行数及订单、电量、费用等汇总值 | 无法判断导入结果是否正确 |

ODS 的 `nvv2t_md_end(1).csv` 只能帮助提出字段问题。除非 ADS 明确将处理后的站点维度以正式合同交付，否则不创建以它为直接来源的生产映射。

## 7. 阶段 A1：首个 ADS 数据集闭环

### 启动条件

ADS 接入门禁材料齐全。首个数据集从 ADS 实际交付中选择，优先顺序为：

1. `dashboard_overview` 或等价总览结果。
2. `fee_energy_daily` 或等价日趋势结果。
3. `station_daily` 或等价站点日结果。

不提前固定物理表名，以 ADS 正式合同为准。

### 代码任务

1. 编写该数据集的 Schema 和 Manifest 样例。
2. 编写 staging 到 `rpt_*` 的显式字段映射。
3. 实现必填、类型、唯一性、范围和对账质量规则。
4. 创建结果表、索引和活动批次过滤视图。
5. 创建对应的 `api_v1_*` 只读视图。
6. 接入现有查询仓储和 API DTO。
7. 完成导入、校验、发布、查询、失败阻断和回滚测试。

### 验收

```text
ADS 样例 + Manifest
  -> staging
  -> 质量校验
  -> rpt_* 结果表
  -> 发布指针
  -> api_v1_* 视图
  -> 查询 API
```

- 同一批次重复导入不产生重复数据。
- 未通过质量规则的批次不可发布。
- API 只读取当前活动批次。
- 回滚后恢复上一已发布批次。
- ADS、结果表、视图和 API 的关键值能够逐层对账。
