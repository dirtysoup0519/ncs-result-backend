## 当前职责

本仓库只接收上游已经处理完成的数据，并负责：

1. 数据集、Schema、Manifest 和来源批次登记。
2. 处理后数据的格式、校验和、唯一性、完整性及基础范围检查。
3. staging 导入、发布、历史版本和明确目标回滚。
4. MySQL 结果表以及面向查询后端的 `api_v1_*` 只读视图。
5. Flask 数据管理 API 和大屏查询 API。
6. 与上游和前端之间稳定的数据及接口合同。
7. 接收外部已训练模型和权重，构造已发布数据集输入，执行受控推理并发布预测结果。

## 当前不负责

- 原始数据清洗、时间修复、特征工程和连续化处理。
- 模型训练、调参和模型效果优化。
- 模型结构的研发；本项目只实现已登记适配器的加载、探针校验、推理和结果发布。
- 预测请求中的在线训练或在线加载任意文件。

本项目负责受控推理闭环：模型同学提供模型结构/权重及输入合同，我们从已发布 `load_hourly` 构造输入，执行 CPU 推理，完成连续性、数值、版本和血缘校验后发布 `load_prediction`。预测失败不回滚已发布 ADS 数据。

## 未来扩展

模型控制面和测试模型适配已在当前 `feature/ads-shell-sync` 分支落地；训练代码仍不在本仓库。模型文件放在 Git 忽略的 `data_exchange/models/`（Windows）或虚拟机运行目录，不进入 Git。
