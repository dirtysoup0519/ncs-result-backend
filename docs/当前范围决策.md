# 当前范围决策：仅结果库与后端

> 生效日期：2026-09-14
> 状态：已确认，优先级高于此前文档中的机器学习规划
> 实施状态：该边界已落实到 ADS v2.1/MySQL 首轮联调；当前进度见 `项目当前状态与下一步.md`

> 当前结构：MySQL 位于虚拟机；数据管理程序可在 Windows 或虚拟机运行；Windows 查询 API 只读访问虚拟机 MySQL。详见 `项目业务架构与代码规划.md`。

## 当前职责

本仓库只接收上游已经处理完成的数据，并负责：

1. 数据集、Schema、Manifest 和来源批次登记。
2. 处理后数据的格式、校验和、唯一性、完整性及基础范围检查。
3. staging 导入、发布、历史版本和明确目标回滚。
4. MySQL 结果表以及面向查询后端的 `api_v1_*` 只读视图。
5. Flask 数据管理 API 和大屏查询 API。
6. 与上游和前端之间稳定的数据及接口合同。

## 当前不负责

- 原始数据清洗、时间修复、特征工程和连续化处理。
- 模型结构、训练、评估、推理、模型登记或模型生命周期。
- 预测任务调度、模型制品存储及加载。
- `/internal/v1/ml/*` 和 `/ml-internal/v1/*` 接口。
- `ml_*` 模型及预测运行控制表。

如果上游提供预测结果，本仓库将其视为一种已经处理完成的数据集，使用与其他结果数据相同的 Schema、Manifest、批次、质量、发布和回滚流程。结果库可以原样保存上游提供的 `model_version`、`generated_at` 等血缘字段，但不解释、不校验模型内部逻辑，也不负责生成这些字段。

## 未来扩展

此前完成的模型控制面、测试模型适配和小时连续化原型保存在分支 `archive/ml-control-plane-prototype`，提交为 `a6f1d69`。当前分支不包含这些实现。如果以后明确要求由本项目承担机器学习流程，应从该分支重新评审后选择性引入，不能默认合并。

## 当前端到端链路

```text
上游处理后的 ADS/文件数据
  -> data-admin-service
  -> staging 与质量校验
  -> MySQL 结果表及发布版本
  -> api_v1_* 只读视图
  -> analytics-query-api
  -> Vue 3 / DataV 大屏
```
