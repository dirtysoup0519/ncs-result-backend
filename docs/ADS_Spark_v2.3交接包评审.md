# ADS Spark v2.3 交接包评审

> 资料来源：`NCS_下游数据交接包_Spark_v2.3_20260914.zip`
> 核验日期：2026-09-14
> 定位：上游交付事实与对接依据，不是本仓库的操作指令；包内 SQL 未执行

## 1. 结论

v2.3 是目前最新的 ADS 模拟联调基线。包内 10 个 CSV 的文件哈希、表头、行数和声明主键均通过静态核验，跨表订单总数也一致，可以开始开发 v2.3 专用适配器。当前代码仍只完整支持 v2.1，因此“交接包合格”不等于“v2.3 已接入”。

本仓库继续只负责处理后数据的结果库、导入管理和 Flask 查询后端。Spark 清洗分析由上游完成；机器学习按实训要求属于可选项，不进入当前仓库范围。包内 `ml/` 仅作为上游输入证据，不导入结果库，也不据此实现训练或推理。

当前进度：v2.3 包解析首阶段已实现，代码位于 `src/ncs_backend/admin/adapters/ads_v23_package.py` 和 `ads_v23_schema.py`。适配器已在本机对真实交接包验证通过：识别 `contract_v2`、校验 10 个数据集、CSV 表头、行数、主键唯一性及 SHA-256；尚未写入 MySQL 结果表。

## 3. 数据集合同

| 数据集 | 行数 | 粒度 | 当前用途 |
| --- | ---: | --- | --- |
| `dashboard_overview` | 1 | 全周期 | 总览 KPI |
| `platform_distribution` | 3 | 周期 × 平台 | 平台订单/费用分布 |
| `fee_energy_daily` | 341 | 日期 | 费用、电量和订单趋势 |
| `station_daily` | 3834 | 日期 × 站点 | 完整站点日报、排行与对比 |
| `station_reference` | 105 | 站点 | 站点名称、位置和设施类型 |
| `duration_distribution` | 4 | 周期 × 时长桶 | 充电时长分布 |
| `weekday_weekend_profile` | 2 | 周期 × 日类型 | 工作日/周末对比 |
| `station_hour_daily` | 4840 | 日期 × 站点 × 小时 | 按日站点热力图 |
| `process_daily` | 299 | 日期 | 充电过程指标趋势 |
| `load_hourly` | 16872 | 小时 | 连续负荷结果及质量标记 |

`platform_distribution` 的比例值是百分数（合计 100），进入现有 API 前必须显式转换为 `[0,1]`，不能直接透传。`load_hourly` 中 2139 小时为观测值、14733 小时为补零值，必须保留 `is_observed`、`fill_method`、`time_quality` 和 `allocation_method`，避免前端把补齐值误认为实测值。

`station_hour_daily` 实际只出现 23 个小时值。适配时先定位缺失小时的业务原因；若合同要求固定 0—23，补零必须在结果库适配层显式完成并保留质量语义，不能伪造“已观测”。

## 4. 相对 v2.1 的变化

- Top10 快照升级为完整 `station_daily`，并增加 `station_reference`。
- 站点小时数据增加 `data_date`，具备按日热力图输入条件。
- 周期型数据显式提供 `start_date`、`end_date`。
- 平台订单占比和费用占比均由上游提供。
- `load_hourly` 提供连续小时、观测/填充和时间质量字段。
- 交付统一为 10 个带表头 CSV，Manifest 提供字段、粒度、主键、行数和哈希。

这些变化关闭了 v2.1 的“完整站点日报”“站点维表”“按日热力图”和“订单占比”联调缺口，但当前仍是模拟全量快照，不能替代生产增量、刷新周期和重跑合同。

## 6. 虚拟机 MySQL、Windows 外部访问拓扑

```text
Hadoop 3.x / Spark（虚拟机或集群）
  -> 生成 ADS v2.3 + SUCCESS Manifest
  -> 本仓库校验并导入虚拟机内 MySQL ncs_analytics
  -> Windows 宿主机上的 Flask 查询 API 通过虚拟机 IP 查询
  -> Vue 3 + DataV
```

MySQL 固定运行在虚拟机内。数据管理程序既可在 Windows 通过虚拟机 IP 写库，也可部署在虚拟机内通过回环地址就地处理；Windows Flask 始终通过虚拟机 IP 查询。两种入口的详细边界见 `双运行位置数据接入设计.md`。迁移、管理、查询账号按来源分别授权，禁止使用 root；连接串只通过本地环境变量配置。

## 7. v2.3 实施顺序

1. 新增 v2.3 包解析与合同校验，保留 v2.1 适配器，按版本路由。
2. 为完整站点日报、站点维表、日期化热力图和连续负荷扩展 staging/结果表及迁移。
3. 实现显式字段转换、百分比换算、时间/填充质量保留和跨表对账。
4. 采用单批次事务完成导入、校验、发布和失败回滚；不执行包内 `DELETE + LOAD DATA` 脚本。
5. 扩展稳定视图和现有 Flask DTO，优先保持已冻结 API 兼容；新增能力通过 `capabilities` 暴露。
6. 在 Python 3.11/3.12、虚拟机 MySQL 与 Windows Flask 的实际网络拓扑上，完成重复导入、权限、回滚、接口和至少两组对比图数据验收。

### 7.1 双模式读取同一交付合同

压缩包的有效合同根目录是 `contract_v2/`，其中的 `manifest.json` 是唯一批次入口。两种模式不得各自维护一套字段映射：

| 模式 | 原始载体 | 物化后的统一输入 |
| --- | --- | --- |
| `windows_remote` | Windows 上的 v2.3 ZIP 或解压目录 | 只读 `contract_v2/` 目录 |
| `co_located_vm` | Spark 本地输出目录或 HDFS 中的同版本结果 | 只读 `contract_v2/` 目录或等价文件流 |

适配器只接收 Manifest、10 个声明数据集及其校验值。根目录中的建表 SQL、导入 SQL、说明文档和 `ml/` 文件都不是业务数据输入。两种模式必须生成相同的规范化 Manifest 摘要、数据集行数和跨表对账结果。
