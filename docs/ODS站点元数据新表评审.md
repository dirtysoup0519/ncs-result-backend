# ODS 站点元数据新表评审

> 本文只记录 ODS 来源证据。本仓库不直接处理 ODS，当前只接收上游 v3.2 包中的 `contract_v2` 结果；业务与架构见 `项目业务架构与代码规划.md`。

> 资料来源：ODS 同学于 2026-09-14 提供的 `nvv2t_md_end(1).csv`
>
> 纳入原则：原始 CSV 不复制到本仓库；本文只保留结果库设计和上游对接所需的结构、质量结论与未决项
>
> 当前用途：仅作为上游来源与站点合同参考；当前结果库以上游 v3.2 的 18 个合同数据集为输入，不直接导入该 ODS 表。

## 1. 结论

该文件已不再是上一版交接包中的重复表头数据，可以作为站点维度的脱敏样例和联调依据。它仍是 ODS 来源表，不是可直接发布给前端的结果表；正式接入时应由上游交付对应 Schema、Manifest、批次信息和字段语义。

## 3. 字段映射建议

| ODS 字段 | 结果库逻辑字段 | 建议类型 | 约束/用途 |
| --- | --- | --- | --- |
| `stationId` | `station_id` | `VARCHAR(64)` | 非空、唯一；不要因为样例为数字就绑定整数类型 |
| `locationId` | `location_id` | `VARCHAR(64)` | 非空、可重复；需要上游解释是区域、地址点还是其他业务位置标识 |
| `facilityType` | `facility_type_code` | `VARCHAR(32)` | 非空；保留源代码，取得枚举字典后再生成显示名称 |
| `station_name` | `station_name` | `VARCHAR(255)` | 非空；用于筛选项、排行和热力图展示 |
| `address` | `address` | `VARCHAR(500)` | 非空；当前仅作站点描述，不据此解析行政区 |
| `device_count` | `device_count` | `INTEGER` | 非空且应大于等于 0；当前样例范围 1～40 |
| `open_time` | `open_hours_text` | `VARCHAR(64)` | 原样保留；未冻结跨午夜、休息时段等复杂格式 |
| `update_time` | `source_updated_date` | `DATE` | 入库时把 `2019/7/26` 规范化为 `2019-07-26`，原值可在 staging 留存 |

API 和 `api_v1_*` 视图继续使用稳定的 `station_id`、`station_name` 等逻辑字段，不直接暴露 ODS 的 camelCase 命名。结果库应额外补充 `batch_id`、`loaded_at` 和来源数据集等血缘字段。

## 4. 对现有功能的影响

- `station_reference` 数据集已有可用样例，可用于站点名称筛选、站点排行名称关联和站点维度完整性校验。
- “站点总数 105”可作为当前样例批次的对账值，不能固化成业务常量。
- `device_count` 可作为静态配置桩数候选，但不能据此推导实时活跃、空闲、占用或故障桩数。
- 当前表没有经纬度和坐标系，仍不能支撑地图定位。
- 当前表没有小时事实数据，因此不能单独关闭“站点 × 小时热力图数据缺失”的问题。

## 5. 仍需向 ODS 同学确认

1. `facilityType` 的 1～4 各自含义及未知值处理规则。
2. `locationId` 的业务定义，以及它与行政区、站点地址的关系。
3. `device_count` 是充电桩数量、充电枪数量还是可用设备数量，是否包含停用设备。
4. `open_time` 的正式格式、是否允许非全天营业和跨午夜区间。
5. `update_time` 表示源记录更新时间、维表快照日期还是数据脱敏日期。
6. 正式批次是否仍保证 `stationId` 唯一，以及删除/停用站点如何表达。
7. 订单或 ADS 中的 `station_id` 与本表 `stationId` 的关联覆盖率和孤儿记录数量。

在上述语义确认前，可以完成结构校验和联调，但不能把代码 1～4 翻译成未经确认的中文类型，也不能把 `device_count` 展示成实时活跃桩数。
